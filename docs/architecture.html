Architecture

One static binary, three servers' worth of behavior, one budget that everything obeys.

brokemode serve runs the gateway in the same process by default, so the dashboard's request table and metrics see live gateway traffic without any cross-process plumbing. brokemode gateway runs it standalone when that's all you want.

The registry is the law

models.yaml defines each model's Ollama tag, quantization, disk size, measured peak RSS, recommended context length for a 16GB box, and aliases — plus the global max_rss_gb budget. Every load path goes through the same check:

  • install.sh refuses to pull models over budget or beyond free disk, with the exact shortfall;
  • bench / gateway refuse to load them, before any request reaches Ollama;
  • doctor classifies every entry as comfortable / tight / no-fit against min(max_rss_gb, memory − 5GB) for the actual machine.

Resolution order: --models-yaml flag → current directory → next to the binary → ~/.brokemode/models.yaml → the copy embedded at build time. A bare release download always runs.

The gateway, carefully

Claude Code will not tolerate a malformed stream, so the SSE sequence is generated by a small state machine and locked down by table-driven tests against a fake Ollama: 

message_start → ping → content_block_start → content_block_delta*
  → content_block_stop → (more blocks…) → message_delta → message_stop
  • Tool calls: Anthropic tool_use blocks become Ollama tool_calls; tool_result blocks become tool-role messages, with tool-use IDs mapped back to tool names (Ollama addresses tools by name). Streaming tool calls emit input_json_delta blocks.
  • Accounting: usage comes from Ollama's native prompt_eval_count / eval_count; stop reasons map stop → end_turn, length → max_tokens, tool calls → tool_use.
  • Instrumentation: every request records TTFT, decode tok/s, tokens in/out, and peak Ollama RSS (sampled at 500ms during the request) — the reason this is a purpose-built gateway and not an off-the-shelf proxy.
  • Auth: any non-empty bearer token or x-api-key; the gateway binds to localhost.

Benchmarks that don't lie

  • Ollama's own nanosecond timing fields (load_duration, prompt_eval_*, eval_*) — no client-side stopwatch guessing.
  • 3 warmup + 5 measured runs per prompt class; median and p95 reported, never the mean.
  • Five prompt classes: short chat, 1k summarization, 4k code review, JSON structured output, and a two-leg tool-call round trip.
  • 1Hz host telemetry per case; no sudo → results marked PARTIAL, never silently degraded. Decode rate sagging >15% across runs → thermal-throttle warning.

Build & release

make build runs the Vite build, then a static go build that embeds web/dist, the registry, and the prompts — so brokemode serve needs no node_modules at runtime, and a release asset is one file. Pushing a v* tag triggers the release workflow: dashboard build, tests, then darwin/linux × arm64/amd64 binaries with sha256 checksums. The installer downloads exactly the one matching the machine.
