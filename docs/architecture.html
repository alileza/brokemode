Architecture.

A purpose-built gateway, honest telemetry, and one memory budget that every code path obeys.

The request path

The big picture

Everything observes; one place aggregates.

Telemetry samplers feed a shared metrics registry alongside per-request gateway numbers; brokemode serve exposes all of it three ways at once.

brokemode serve runs the gateway in the same process by default, so the dashboard's request table and metrics see live gateway traffic without cross-process plumbing. brokemode gateway runs it standalone when that's all you want.

The registry is the law

One budget, enforced everywhere.

models.yaml defines each model's Ollama tag, quantization, disk size, measured peak RSS, recommended context length for a 16GB box, and aliases — plus the global max_rss_gb budget. Every load path goes through the same check.

⛨

install.sh

Refuses to pull models over budget or beyond free disk, reporting the exact shortfall in GB.

✕

bench & gateway

Refuse to load over-budget models before any request reaches Ollama — a 400 with the numbers, never an OOM.

✓

doctor

Classifies every entry as comfortable / tight / no-fit against min(max_rss_gb, memory − 5GB) for the actual machine.

Resolution order: --models-yaml flag → current directory → next to the binary → ~/.brokemode/models.yaml → the copy embedded at build time. A bare release download always runs.

The gateway, carefully

An SSE stream Claude Code will accept.

Claude Code will not tolerate a malformed stream, so the sequence is generated by a small state machine and locked down by table-driven tests against a fake Ollama.

message_start → ping → content_block_start → content_block_delta* → content_block_stop → (more blocks…) → message_delta → message_stop
⚒

Tool calls

tool_use blocks become Ollama tool_calls; tool_result blocks become tool-role messages, with tool-use IDs mapped back to tool names. Streaming tool calls emit input_json_delta blocks.

Σ

Accounting

usage comes from Ollama's native prompt_eval_count / eval_count; stop reasons map stop → end_turn, length → max_tokens, tool calls → tool_use.

◔

Instrumentation

Every request records TTFT, decode tok/s, tokens in/out, and peak Ollama RSS — the reason this is a purpose-built gateway and not an off-the-shelf proxy.

Benchmarks that don't lie

Native timings, median and p95.

  • Ollama's own nanosecond timing fields (load_duration, prompt_eval_*, eval_*) — no client-side stopwatch guessing.
  • 3 warmup + 5 measured runs per prompt class; median and p95 reported, never the mean.
  • Five prompt classes: short chat, 1k summarization, 4k code review, JSON structured output, and a two-leg tool-call round trip.
  • 1Hz host telemetry per case; no sudo → results marked PARTIAL, never silently degraded. Decode rate sagging >15% across runs → thermal-throttle warning.

Build & release

Tag it, ship one file.

make build runs the Vite build, then a static go build that embeds web/dist, the registry, and the prompts — so serve needs no node_modules at runtime, and a release asset is one file.

$ git tag v0.1.0 && git push origin v0.1.0 # → GitHub Actions: dashboard build, tests, then # brokemode-{darwin,linux}-{arm64,amd64} + sha256 checksums. # install.sh downloads exactly the one matching the machine.
